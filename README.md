# Erfolg

Next.js, PostgreSQL/Prisma, NextAuth, Selectel S3.

## Локальный запуск

1. `npm ci`
2. Заполнить `.env` по `.env.example`. Для разработки использовать отдельную БД.
3. `npm run db:generate`
4. Для новой БД: `npm run db:deploy`. Сидирование запускать только осознанно: оно меняет данные каталога.
5. `npm run dev`

Проверки: `npm run check`. Сборка: `npm run build`.

## Деплой

Боевой сервер — Selectel: systemd + nginx, standalone-сборка Next.

## Настройки

- `NEXT_PUBLIC_SITE_URL` — полный адрес сайта без завершающего `/`.
- `NEXT_PUBLIC_SEO_BLOCK_INDEX=true` — страницы отдают `noindex`; обход разрешён, чтобы поисковики могли прочитать это правило.
- `NEXT_PUBLIC_FORMS_DISABLED=true` — отключает формы и аналитику независимо от индексации.
- `TRUST_PROXY=true` включать только за доверенным reverse proxy, который перезаписывает `X-Forwarded-For` (nginx с `proxy_set_header X-Forwarded-For $remote_addr`). Без этой настройки работают лимиты по учётной записи и телефону, но не по IP.
- Лимиты запросов общие для экземпляров приложения: временные записи `internal.rate-limit:*` в существующей таблице `settings`. Значения идентификаторов хешируются; записи старше суток очищаются при обращениях.
- Изменение администратора отзывает его старые сессии по `updatedAt`. Вход обновляет только `lastLoginAt`, сохраняя эту версию.
- S3-бакет должен оставаться закрытым. `/media` публикует только `products/`; документы заявок `requests/` не должны быть публичными.

Внесённые исправления не требуют изменения схемы существующей БД. При обновлении зависимостей и генерации Prisma на Windows предварительно остановить локальный dev-сервер, если он удерживает DLL.

Автоматическая браузерная проверка отключена по правилам проекта.
